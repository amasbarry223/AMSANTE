    38→## 2. DIRECTION ARTISTIQUE
    39→
    40→### 2.1 Concept : « Le soin, sans papier »
    41→Le récit visuel du site est **la transformation du papier en confiance digitale** : les dossiers, les feuilles de soins et les cartes cartonnées se dissolvent en particules qui se recomposent en une **carte d'assuré lumineuse**, l'objet signature de la marque. Cette carte revient comme fil rouge dans tout le site (hero, souscription, confirmation, vérification).
    42→
    43→**Références de ton et de qualité** (s'inspirer du niveau, ne rien copier) : la clarté produit de Stripe et Linear, la chaleur et l'illustration des néo-assureurs santé type Alan ou Oscar, la narration au scroll des lauréats Awwwards en fintech/santé. **Résultat attendu** : premium, lumineux, rassurant, humain, jamais froid ni « clinique ».

    47→- Photographies : personnes maliennes réelles dans des situations de soin et de vie quotidienne, lumière naturelle chaude. En dev : placeholders `next/image` avec `blurDataURL`, dossier `/public/images/placeholders`.

    84→## 3. SYSTÈME DE MOTION : LA RÈGLE DE COHÉRENCE
    85→
    86→Le site doit sembler animé par **une seule main**. Toutes les animations passent par des tokens centralisés dans `lib/motion/tokens.ts`.
    87→
    88→```ts
    89→export const ease = {
    90→  out: [0.16, 1, 0.3, 1],        // "expo.out" : entrées, révélations
    91→  inOut: [0.65, 0, 0.35, 1],     // transitions de page, morphings
    92→  spring: { type: "spring", stiffness: 260, damping: 26 }, // UI interactive
    93→};
    94→export const duration = { micro: 0.18, fast: 0.35, base: 0.6, slow: 1.0, story: 1.4 };
    95→export const stagger = { tight: 0.04, base: 0.08, loose: 0.14 };
    96→```
    97→Les mêmes valeurs sont enregistrées dans GSAP via `CustomEase.create("amsOut", "0.16,1,0.3,1")`.
    98→
    99→**Partage des responsabilités (règle absolue : jamais deux librairies sur le même élément)**
   100→| Outil | Rôle |
   101→|---|---|
   102→| **GSAP + ScrollTrigger + SplitText** | Tout ce qui dépend du scroll : sections épinglées, scrub, révélations de titres, tracés SVG, parallaxe |
   103→| **Motion (`motion/react`)** | États d'interface : hover, tap, layout animations, `AnimatePresence`, étapes du tunnel, modales, toasts, compteurs |
   104→| **Lenis** | Défilement fluide global, synchronisé avec `ScrollTrigger.update` via `gsap.ticker` |
   105→| **React Three Fiber + drei** | Une seule scène 3D signature (hero) + une scène légère réutilisée (carte en confirmation) |
   106→| **View Transitions / `template.tsx`** | Transitions entre pages |
   107→
   108→**Vocabulaire de mouvement (et rien d'autre)**
   109→1. **Révélation de titre** : SplitText par lignes, chaque ligne monte depuis un masque (`yPercent: 110 → 0`), `duration.slow`, `stagger.base`, `amsOut`.
   110→2. **Apparition de bloc** : `opacity 0 → 1`, `y 24 → 0`, `duration.base`, déclenché à 80 % du viewport, une seule fois.
   111→3. **Hover carte** : élévation `y -4`, ombre renforcée, inclinaison 3D légère (≤ 6°) suivant la souris (desktop uniquement).
   112→4. **Bouton magnétique** pour les CTA principaux : attraction ≤ 10 px, ressort `ease.spring`.
   113→5. **Compteur** : montants interpolés avec un ressort Motion (`useSpring` + `useTransform`), jamais de saut brut.
   114→6. **Tracé** : les motifs bogolan et les lignes de timeline se dessinent au scroll (`stroke-dashoffset`).
   115→7. **Transition de page** : rideau teal qui monte puis se retire (0,6 s), le titre de la page suivante se révèle ensuite.
   116→
   117→**Garde-fous**
   118→- `prefers-reduced-motion: reduce` → Lenis désactivé, scrub remplacé par de simples fondus, 3D remplacée par une image fixe, durées ≤ 0,2 s.
   119→- Curseur personnalisé (point + anneau qui grossit sur les éléments interactifs) **uniquement** sur pointeur fin (`(pointer: fine)`), jamais de masquage du curseur natif sur les champs de saisie.
   120→- Aucune animation ne bloque une action : un CTA est cliquable dès son apparition.
   121→- Nettoyage systématique : `useGSAP()` (`@gsap/react`) avec `scope`, `ScrollTrigger.refresh()` après chargement des polices et images.

   218→
   219→Principes communs à tous les tunnels :
   220→- **Une décision par écran**, bouton principal toujours au même endroit, retour possible sans perte.
   221→- Stepper en haut (Motion `layoutId` pour l'indicateur), progression en %.
   222→- Transitions entre étapes : glissement horizontal de 40 px + fondu (`AnimatePresence mode="wait"`), direction inversée au retour.
   223→- Récapitulatif vivant (colonne de droite sur desktop, sticky) qui se met à jour à chaque saisie avec la prime animée.
   224→- Sauvegarde automatique (zustand persist) + bandeau « Reprendre ma souscription » si l'utilisateur revient.
   225→- Validation zod en ligne, messages d'erreur humains (« Ce numéro doit contenir 8 chiffres après +223 »).
   226→- États vides, chargement (skeletons au rythme du motion system) et erreurs conçus pour chaque écran.

   228→### 8.1 Souscription particulier / famille : `/souscrire`

   231→3. **Vos informations** : nom, téléphone (+223), e-mail facultatif, adresse (commune / quartier), pièce d'identité (NINA ou autre).
   232→4. **Documents** : photo d'identité de chaque bénéficiaire et pièce d'identité (dropzone, aperçu, recadrage carré, compression automatique < 300 Ko).
   233→5. **Récapitulatif et signature** : récap complet, cases de consentement (CGU, traitement des données), signature par **code OTP envoyé par SMS** (OTPInput).
   234→6. **Paiement Mobile Money** : choix de l'opérateur (Orange Money, Moov Africa Money, Wave : grandes tuiles avec leurs couleurs), numéro payeur, bouton `Payer 12 500 FCFA`. Écran d'attente : « Validez le paiement sur votre téléphone », animation de téléphone qui vibre, compte à rebours de 2 min, sondage du statut (`getPaymentStatus`) toutes les 3 s. Gestion succès / refus / expiration avec option « Réessayer » ou « Changer de moyen de paiement ».
   235→7. **Confirmation** (`/souscrire/confirmation`) : moment signature. Confettis sobres teal/ocre, puis la **carte d'assuré 3D se matérialise** (particules → carte), retournable au clic. Actions : `Télécharger ma carte (PDF)`, `Ajouter à l'écran d'accueil`, `Accéder à mon espace` → `/connexion`. Rappel des prochaines étapes (délai de carence, activation du compte).

   278→## 9. PERFORMANCE : CONTEXTE MALI / RÉSEAU MOBILE
   279→
   280→Le site doit être spectaculaire sur une bonne connexion **et** rester rapide en 3G/4G à Bamako.
   281→- Budgets : JS initial de l'accueil ≤ 180 Ko gzip (hors chunk 3D) ; LCP ≤ 2,5 s en 4G ; CLS ≤ 0,05 ; INP ≤ 200 ms. Lighthouse ≥ 90 sur les 4 catégories (mobile), ≥ 95 desktop.
   282→- Three.js, MapLibre, ZXing, Fuse : **imports dynamiques** (`next/dynamic`, `ssr: false`), chargés après l'interaction ou à l'approche du viewport (`IntersectionObserver`).
   283→- Chargement 3D conditionnel : seulement si `(pointer: fine)`, largeur ≥ 1024 px, pas de `navigator.connection.saveData`, `effectiveType` ≠ `2g/3g`, GPU tier ≥ 2. Sinon fallback image.
   284→- Scène 3D : géométries simples, textures KTX2 / ≤ 512 px, `dpr={[1, 1.5]}`, `frameloop="demand"` quand la scène est hors écran, pause sur `visibilitychange`.
   285→- Images : `next/image` AVIF/WebP, `sizes` correct, `priority` uniquement sur l'image LCP.
   286→- Polices : 2 familles max + mono, `preload` uniquement du poids titre.
   287→- Server Components par défaut ; `"use client"` uniquement pour les îlots interactifs.
